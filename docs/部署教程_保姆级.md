# NL2SQL 保姆级部署教程

> 面向:第一次把这个项目部署上线的你。
> 依据:本教程命令与 [`docs/部署手册.md`](部署手册.md)、`deploy/` 配置文件、后端 `application.yml` / `application-dev.yml`、`pom.xml`、`DataInitializer` 实际代码逐项核对后编写。凡代码现状与简版手册有出入处,本教程已在对应步骤标注【补正】并给出可直接复制的修复命令。
> 目标环境:阿里云 ECS(2 核 2G + 40G ESSD + 3M 带宽),Ubuntu 22.04 LTS。
> 最终产物:浏览器访问 `http://<ECS公网IP>` 能登录、能用自然语言问数。

---

## 0. 部署总览(先看懂再动手)

### 0.1 你将得到什么

一条完整链路:`用户输入自然语言 → Spring Boot 调通义千问生成 SQL → 校验 → MySQL 只读执行 → 返回结果`。前端 Vue3 页面为可选(默认只部署后端 API),观测用 LangFuse Cloud(可选,不配也能跑)。

### 0.2 部署拓扑(与代码一致)

```
ECS (2核2G, Ubuntu 22.04)
 ├── JDK 17 + Spring Boot 应用   监听 8080,JVM -Xmx960m
 ├── Nginx                        监听 80,反代 /api/ → 8080
 ├── Docker MySQL 8.0             --memory=512m,只绑 127.0.0.1:3306
 └── Caffeine 本地缓存             随应用进程,替代 Redis

外部服务(不占 ECS 资源)
 ├── 通义千问 DashScope API        必需,问数靠它
 └── LangFuse Cloud               可选,不配则降级 no-op
```

### 0.3 部署前准备清单(全部备齐再开始,避免中途卡壳)

| # | 准备项 | 在哪办 | 说明 |
|---|---|---|---|
| 1 | 阿里云 ECS 一台 | 阿里云控制台 | 2 核 2G,Ubuntu 22.04 LTS,记下**公网 IP** 和 root 密码 |
| 2 | 安全组放行端口 | 阿里云控制台 | 22(限你的 IP)、80(全网),**不要**开 8080/3306 |
| 3 | 通义千问 API Key | 阿里云百炼 DashScope 控制台 | 申请 `sk-...`,问数必需 |
| 4 | LangFuse 密钥(可选) | cloud.langfuse.com 注册 | `pk-lf-...` / `sk-lf-...`,不配就跳过 |
| 5 | 一个 MySQL root 密码 | 你自己定 | 自己造一个强密码,如 `Dili@2026!secure` |
| 6 | 一个 JWT 密钥 | 你自己定 | ≥32 字节随机串,见第 2 步生成命令 |
| 7 | 本地装好 Maven + JDK 17 | 你的电脑 | 用于构建 jar;或用服务器 Docker 多阶段构建(第 5 步二选一) |

> **关于模型**:代码默认用 `qwen-turbo`(开发省钱)。生产想要更高质量,把环境变量 `DASHSCOPE_MODEL` 改成 `qwen-plus` 或 `qwen-max` 即可,无需改代码。

## 1. 第一步:买 ECS 与配安全组

1. 阿里云控制台买一台 99 元/年的 ECS(2核2G + 40G ESSD + 3M 带宽),系统选 **Ubuntu 22.04 LTS**。
2. 创建时设好 root 密码,或绑定 SSH 密钥对。
3. 进入「云服务器 ECS → 安全组」,给该 ECS 的安全组加两条入方向规则:

| 端口范围 | 授权对象 | 说明 |
|---|---|---|
| 22/22 | `<你的家庭/公司公网 IP>`/32 | SSH,**禁止**填 `0.0.0.0/0` |
| 80/80 | `0.0.0.0/0` | Nginx 对外入口 |

> **不要**开 8080(Spring Boot 直接对外有风险)和 3306(MySQL 只给本机)。

### 验证
```bash
# 在你的电脑上
ssh root@<ECS公网IP>
# 能进 shell 即 OK;进不去检查安全组 22 端口和你 IP 是否填对
```

## 2. 第二步:本地准备好四把"钥匙"(敏感信息)

**原则:这些值只放进服务器的环境变量文件,绝不写进代码、绝不提交 git。** `.gitignore` 已排除 `.env`、`application-*-secret.yml`。

```bash
# 在你本地电脑生成各值(用 git bash / WSL / Linux 均可)

# 2.1 MySQL root 密码(自己定,这里给个生成示例)
openssl rand -base64 18        # 输出类似 Dili@2026!secure... 记下

# 2.2 JWT 密钥(≥32 字节)
openssl rand -base64 32         # 输出类似 b3x...8kQ  记下

# 2.3 通义千问 API Key
# 去阿里云百炼 DashScope 控制台 https://bailian.console.aliyun.com 创建,得 sk-...

# 2.4 LangFuse(可选)
# 去 https://cloud.langfuse.com 注册免费 Hobby 版,创建 project,得 pk-lf-... / sk-lf-...
```

把这四个值记在一个本地记事本里(别丢,后面第 6 步要往服务器粘)。下文用占位符代替:
- `<MYSQL_PWD>` = 你的 MySQL 密码
- `<JWT_SECRET>` = 你的 JWT 密钥
- `<DASHSCOPE_KEY>` = 你的通义千问 key
- `<LANGFUSE_PK>` / `<LANGFUSE_SK>` = LangFuse 公/私钥(可选)

## 3. 第三步:SSH 登录,初始化服务器

```bash
ssh root@<ECS公网IP>
```

进入后,依次执行:

```bash
# 3.1 更新源 + 装基础依赖(nginx / jdk17 / docker / curl)
apt update && apt install -y nginx openjdk-17-jre-headless docker.io curl

# 3.2 开 2G swap(2G 内存机器必须,否则 OOM)
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

### 验证
```bash
java -version          # 应输出 openjdk version "17" 字样
docker --version      # 应输出 Docker version 2x.x.x
nginx -v              # 应输出 nginx version: nginx/1.x
swapon --show         # 应看到 /swapfile  2G  ...
```

## 4. 第四步:启动 MySQL 容器

```bash
# 4.1 建数据目录
mkdir -p /data/mysql

# 4.2 启动 MySQL 8.0(内存限 512m,只绑本机 127.0.0.1,开机自启)
docker run -d \
  --name mysql \
  --memory=512m \
  --restart=always \
  -p 127.0.0.1:3306:3306 \
  -e MYSQL_ROOT_PASSWORD=<MYSQL_PWD> \
  -e MYSQL_DATABASE=nl2sql \
  -v /data/mysql:/var/lib/mysql \
  mysql:8.0
```

> **Flyway 迁移 OOM 注意**:应用首次启动会自动跑 Flyway 建表脚本(V1~V6),如果因 MySQL 512m 内存不够而迁移失败,临时把容器扩到 768m,迁移完再调回 512m:
> ```bash
> docker update --memory=768m mysql   # 迁移前临时扩容
> # 重启应用触发迁移(见第 6 步)
> docker update --memory=512m mysql   # 迁移成功后调回
> ```

### 验证
```bash
docker ps                         # STATUS 列应为 Up
docker exec -it mysql mysql -uroot -p<MYSQL_PWD> -e "SELECT 1"
# 输出 1 即 OK;报错密码不符则检查上一步 MYSQL_ROOT_PASSWORD
```

## 5. 第五步:构建应用 jar(二选一)

### 方式 A:本地构建 + scp 上传(推荐,快)

```bash
# 在你本地电脑,项目根目录
mvn package -DskipTests
# 产物路径:target/nl2sql-app-0.0.1-SNAPSHOT.jar

# 先在服务器建目录(scp 到不存在的路径会报 "No such file or directory")
ssh root@<ECS公网IP> "mkdir -p /opt/nl2sql"

# 上传到服务器并改名为 nl2sql-app.jar(与 systemd 配置对齐)
scp target/nl2sql-app-0.0.1-SNAPSHOT.jar root@<ECS公网IP>:/opt/nl2sql/nl2sql-app.jar
```

> 【补正 1】`/opt/nl2sql` 目录在服务器上默认不存在,**必须先 `ssh ... "mkdir -p /opt/nl2sql"` 再 scp**,否则报 `dest open "/opt/nl2sql/nl2sql-app.jar": No such file or directory`。原简版手册把建目录放在后面步骤,但第 5 步就要往里放 jar,顺序对不上,本教程把建目录提前到上传前。
>
> 【补正 2】简版手册写的是 `scp target/nl2sql-app-*.jar ...`,在 PowerShell 下通配符不展开会报错。本教程给明确文件名 `nl2sql-app-0.0.1-SNAPSHOT.jar`(`pom.xml` `<version>0.0.1-SNAPSHOT</version>` 且无 `<finalName>`,故产物名固定)。
>
> **关于密码**:上面 `ssh` 和 `scp` 各会问一次服务器密码(两次)。想免密,可后续配 SSH 密钥对(`ssh-copy-id root@<IP>`),现在先这么传过去。

### 方式 B:服务器上用 Dockerfile 多阶段构建(无需本地装 Maven)

```bash
# 在服务器上,把仓库代码弄上去(任选:git clone 或 scp 整个项目目录)
cd /path/to/20260818_java_agent
docker build -t nl2sql-app -f deploy/Dockerfile .

# 先建目标目录(docker cp 到不存在的父目录会报错)
mkdir -p /opt/nl2sql

# 把构建好的 jar 从镜像里拷到 /opt/nl2sql
docker create --name tmp nl2sql-app
docker cp tmp:/app/app.jar /opt/nl2sql/nl2sql-app.jar
docker rm tmp
```

### 验证(在服务器上)
```bash
ls -lh /opt/nl2sql/nl2sql-app.jar
# 应看到一个 40~60MB 左右的 jar 文件
```

## 6. 第六步:配环境变量 + 装 systemd 服务

### 6.1 准备目录与权限

```bash
mkdir -p /opt/nl2sql/logs
chown -R www-data:www-data /opt/nl2sql
```

> 【补正】`deploy/nl2sql-app.service` 里 `User=www-data`,但简版手册没提权限。若 `/opt/nl2sql` 的 owner 是 root,www-data 账号读不到 jar、写不了日志,服务会起不来。

### 6.2 写环境变量文件

```bash
cat > /etc/default/nl2sql-app <<'EOF'
# === 数据库 ===
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=nl2sql
DB_USERNAME=root
DB_PASSWORD=<MYSQL_PWD>

# === 通义千问 ===
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_API_KEY=<DASHSCOPE_KEY>
DASHSCOPE_MODEL=qwen-turbo

# === JWT ===
JWT_SECRET=<JWT_SECRET>

# === LangFuse(可选,不配则自动降级 no-op)===
LANGFUSE_PUBLIC_KEY=<LANGFUSE_PK>
LANGFUSE_SECRET_KEY=<LANGFUSE_SK>
LANGFUSE_BASE_URL=https://jp.cloud.langfuse.com

# === Spring profile(默认 dev 即可,所有差异靠上面环境变量覆盖)===
SPRING_PROFILES_ACTIVE=dev
EOF
chmod 600 /etc/default/nl2sql-app
```

> 【补正】相对简版手册,这里补了 `DB_PORT`、`DB_NAME`、`DB_USERNAME`、`DASHSCOPE_BASE_URL`、`SPRING_PROFILES_ACTIVE` —— 它们与 `application-dev.yml` 读取的变量名一一对应,缺了虽能跑(有默认值),但写全更稳。
>
> **变量名必须与代码一致**,源自 `src/main/resources/application-dev.yml`:
> ```yaml
> url: jdbc:mysql://${DB_HOST:127.0.0.1}:${DB_PORT:3306}/${DB_NAME:nl2sql}...
> username: ${DB_USERNAME:root}
> password: ${DB_PASSWORD:}
> api-key: ${DASHSCOPE_API_KEY:}
> secret: ${JWT_SECRET:}
> public-key: ${LANGFUSE_PUBLIC_KEY:}
> ```
> 改了任何一个变量名 = 连不上数据库/模型。

### 6.3 装 systemd 服务

> 这一步要把仓库里的 `deploy/nl2sql-app.service` 放到 `/etc/systemd/system/`。**方式 A(本地 scp jar)用户服务器上没仓库**,不能 cp,改用 scp 直传;**方式 B 用户仓库在服务器上**,用 cp。

**方式 A** —— 在本地 PowerShell 执行,直接 scp 到目标:
```powershell
scp deploy/nl2sql-app.service root@<ECS公网IP>:/etc/systemd/system/
```

**方式 B** —— 在服务器 shell 执行 cp(`/path/to/...` 换成你的实际仓库路径,或 cd 到仓库后用相对路径):
```bash
cp /path/to/20260818_java_agent/deploy/nl2sql-app.service /etc/systemd/system/
# 或 cd 到仓库后用相对路径:cp deploy/nl2sql-app.service /etc/systemd/system/
```

文件就位后,两种方式都在服务器上继续(重载 + 开机自启 + 启动):
```bash
systemctl daemon-reload
systemctl enable nl2sql-app
systemctl start nl2sql-app
```

### 6.4 验证服务
```bash
systemctl status nl2sql-app
# 应为 active (running)

# 看启动日志(关键:Flyway 是否迁移成功、DataInitializer 是否预置账号)
journalctl -u nl2sql-app -n 100 --no-pager
# 期望看到 "Successfully applied 6 migrations" 之类
# 期望看到应用 Started in xx seconds
```

> 首次启动会自动完成两件事,无需你手动建表:
> 1. **Flyway** 跑 `V1~V6` 建表(orders/users/metric_definitions/audit_logs/feedback_queue/session_records/schema_* 等);
> 2. **DataInitializer** 预置 4 个系统账号(admin/operator/product/manager)。

## 7. 第七步:Nginx 反向代理

### 7.1 装配置

> 这一步把仓库里的 `deploy/nginx.conf` 放到 `/etc/nginx/sites-available/`(改名 `nl2sql.conf`)。方式 A 用 scp 直传,方式 B 用 cp。

**方式 A** —— 在本地 PowerShell 执行(scp 时直接改名 `nl2sql.conf`):
```powershell
scp deploy/nginx.conf root@<ECS公网IP>:/etc/nginx/sites-available/nl2sql.conf
```

**方式 B** —— 在服务器 shell 执行 cp:
```bash
cp /path/to/20260818_java_agent/deploy/nginx.conf /etc/nginx/sites-available/nl2sql.conf
# 或 cd 到仓库后:cp deploy/nginx.conf /etc/nginx/sites-available/nl2sql.conf
```

配置就位后,两种方式都在服务器上继续(建软链 + 去默认站 + 重载):
```bash
ln -s /etc/nginx/sites-available/nl2sql.conf /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default
nginx -t
systemctl reload nginx
```

### 7.2 【补正】开放健康检查端点(强烈建议)

仓库里的 `nginx.conf` **只代理了 `/api/`**,没代理 `/actuator/`。简版手册让你 `curl http://<IP>/actuator/health`,但经 80 端口会 404,而 8080 安全组又关了 —— 验证不通。

修复:编辑 `/etc/nginx/sites-available/nl2sql.conf`,在 `location /api/ {}` 块**后面**加一个仅放行 health 的 location(metrics 不放,防泄露):

```nginx
    # 健康检查(只放行 health,不放 metrics 防指标泄露)
    location = /actuator/health {
        proxy_pass http://127.0.0.1:8080;
        access_log off;
    }
```

改完重载:
```bash
nginx -t && systemctl reload nginx
```

### 7.3 验证
```bash
# 在你的电脑上
curl http://<ECS公网IP>/actuator/health
# 应返回 {"status":"UP"}
```

## 8. 第八步:日志轮转

> 把仓库里的 `deploy/logrotate.conf` 放到 `/etc/logrotate.d/`(改名 `nl2sql-app`)。方式 A 用 scp 直传,方式 B 用 cp。

**方式 A** —— 在本地 PowerShell 执行(scp 时直接改名):
```powershell
scp deploy/logrotate.conf root@<ECS公网IP>:/etc/logrotate.d/nl2sql-app
```

**方式 B** —— 在服务器 shell 执行 cp:
```bash
cp /path/to/20260818_java_agent/deploy/logrotate.conf /etc/logrotate.d/nl2sql-app
# 或 cd 到仓库后:cp deploy/logrotate.conf /etc/logrotate.d/nl2sql-app
```

> **现状说明**:`logrotate.conf` 针对的是 `/opt/nl2sql/logs/*.log`。但 Spring Boot 默认日志输出到 stdout(被 systemd 收进 journalctl),**不一定**写文件。也就是说:
> - 默认情况:日志走 `journalctl -u nl2sql-app`,这份 logrotate 不会触发(目录里没文件);
> - 如果你想让日志也落盘(便于排查/归档),需在 `src/main/resources/` 加 `logback-spring.xml` 配 file appender 输出到 `/opt/nl2sql/logs/`,这份 logrotate 才生效。本教程不强制改代码,日常用 `journalctl` 即可。

### 验证
```bash
logrotate -d /etc/logrotate.d/nl2sql-app
# -d 是 dry-run,应无 "error" 字样
```

## 10. 第十步(可选):部署前端 Vue3

默认 Nginx 只代理后端 API,前端是**可选**的。要带页面,按下面做。

### 10.1 本地构建前端
```bash
cd frontend
npm install
npm run build
# 产物:frontend/dist/
```

> **无需配后端地址**:`frontend/src/api/index.ts` 里 `baseURL: '/api/v1'` 是相对路径,浏览器访问 `http://<ECS公网IP>/` 时自动同源走 Nginx 代理转发到后端 8080。所以**既不用改前端代码,也不用配 `VITE_API_BASE_URL` 之类环境变量**,build 出来的 dist 拷上去直接能用。

```bash
# 先在服务器建目录(scp 到不存在的路径会报错)
ssh root@<ECS公网IP> "mkdir -p /opt/nl2sql/frontend"

# 上传整个 dist 目录(scp -r dist 会在 frontend/ 下生成 dist/)
scp -r dist root@<ECS公网IP>:/opt/nl2sql/frontend/

# 确认产物到位
ssh root@<ECS公网IP> "ls /opt/nl2sql/frontend/dist/index.html"
# 应输出 /opt/nl2sql/frontend/dist/index.html
```

### 10.2 打开 Nginx 前端配置
编辑 `/etc/nginx/sites-available/nl2sql.conf`,把仓库里被注释的三行前端配置取消注释:
```nginx
    # 前端静态资源
    root /opt/nl2sql/frontend/dist;
    index index.html;

    # SPA 路由回退(放在 server 块内、location /api/ 之外)
    location / {
        try_files $uri $uri/ /index.html;
    }
```

重载:
```bash
nginx -t && systemctl reload nginx
```

### 验证
浏览器开 `http://<ECS公网IP>`,应见登录页,用 `admin / admin123` 登录。

### 11.3 验证 LangFuse 观测(配了 LangFuse 才做)

`LangfuseClient` 在 key 不为空时,每次问数会异步往 `{base}/api/public/ingestion` 发 trace。验证它真的发上去了:

**1. 服务器侧看有无发送失败** —— 问数一次后查应用日志:
```bash
journalctl -u nl2sql-app --since "5 min ago" | grep -i langfuse
```
- **无输出** = 发送正常(或已静默降级),继续第 2 步确认;
- 出现 `langfuse send failed (degraded, ignored)` = 发送失败(key 错或网络不通),但**不影响问数功能**(已降级)。排查连通性:
  ```bash
  curl -u <LANGFUSE_PK>:<LANGFUSE_SK> https://jp.cloud.langfuse.com/api/public/ingestion -I
  # 期望 4xx(如 400/405 表示鉴权通过、端点存在)而非 401/000(鉴权失败/网络不通)
  ```

**2. LangFuse 控制台看 trace** —— 打开 https://jp.cloud.langfuse.com 登录你创建 project 的账号,进 Traces 列表,应看到刚才那次问数的 trace 记录(含 question、生成的 SQL、耗时、token、置信度、缓存命中)。

**3. 没配 LangFuse 也能跑** —— 若你跳过了第 0 步的 LangFuse key,`LangfuseClient.enabled=false`,问数功能完全不受影响,只是没有观测数据。这是设计如此(降级 no-op),后端 + 前端照常工作。

走到这一步全部成功,部署完成。

## 12. 第十二步(可选):上 HTTPS(两条路,二选一)

到这一步网站是 HTTP 明文。上 HTTPS 有两条路,**按你有没有域名选**:

| 方案 | 适合 | 证书来源 | 浏览器表现 |
|---|---|---|---|
| **12A 自签名证书** | 没有域名,直接用 `https://<公网IP>` 访问(演示项目推荐) | 自己生成,有效期 10 年,**无需续期** | 地址栏有锁标但提示"不安全",首次访问需手动点一次"继续前往" |
| **12B 域名 + Let's Encrypt** | 有域名(大陆 ECS 还需 ICP 备案通过) | Let's Encrypt 免费,90 天,自动续期 | 正式可信证书,无任何警告 |

> **大陆地域重要提醒**:你的 ECS 若在北京等大陆地域,**域名访问 80/443 必须先完成 ICP 备案**,未备案域名会被阻断;而**裸 IP 访问不需要备案**(这也是你 `http://<IP>` 一直能访问的原因)。没有域名或不想备案,直接走 12A。

---

## 12A. 方案一(无域名):自签名证书,`https://<公网IP>` 直接访问

Let's Encrypt 不给裸 IP 签常规证书,所以无域名时用**自签名证书**:加密强度与正规证书完全相同,只是没有第三方 CA 做担保,浏览器会弹一次警告。演示/自用场景可忽略这个代价。

### 12A.1 放行 443 端口
阿里云控制台 → 云服务器 ECS → 安全组 → 加一条入方向规则:

| 端口 | 授权对象 | 说明 |
|---|---|---|
| 443 | `0.0.0.0/0` | HTTPS 入口 |

### 12A.2 生成自签名证书(服务器上执行)

```bash
mkdir -p /etc/nginx/ssl
openssl req -x509 -nodes -days 3650 -newkey rsa:2048 \
  -keyout /etc/nginx/ssl/nl2sql.key \
  -out /etc/nginx/ssl/nl2sql.crt \
  -subj "/CN=<ECS公网IP>" \
  -addext "subjectAltName=IP:<ECS公网IP>"
```

> - 有效期 10 年(`-days 3650`),自签名没有 CA 续期问题,一次生成长期使用(不像 12B 要配自动续期);
> - **`subjectAltName` 里的 IP 必须写**:新版 Chrome/Edge 只认 SAN 不认 CN,漏了会直接拒绝连接;
> - 两处 `<ECS公网IP>` 换成你的真实公网 IP(如 `123.57.53.23`)。

### 12A.3 给 Nginx 加 443 监听
编辑 `/etc/nginx/sites-available/nl2sql.conf`,在 server 块顶部(`listen 80;` 下面)加三行,其余全部不动:

```nginx
server {
    listen 80;
    listen 443 ssl;                                    # ← 新增
    ssl_certificate     /etc/nginx/ssl/nl2sql.crt;     # ← 新增
    ssl_certificate_key /etc/nginx/ssl/nl2sql.key;     # ← 新增
    server_name _;

    # ...root / location /api/ / health / location / 保持原样
```

80 和 443 共用同一个 server 块,HTTP 与 HTTPS 都能访问,无需做跳转。重载:

```bash
nginx -t && systemctl reload nginx
```

### 12A.4 验证

```bash
# 在你的电脑上(-k 表示跳过证书校验,自签名必须加,否则报证书无效)
curl -k https://<ECS公网IP>/actuator/health
# 期望 {"status":"UP"}
```

浏览器开 `https://<ECS公网IP>` → 出现"您的连接不是私密连接"警告 → 点**高级** → **继续前往** → 见到登录页,地址栏有锁标(带"不安全"字样属预期)。前端 axios `baseURL: '/api/v1'` 是相对路径,自动走 HTTPS,无需改前端。

> 【与 12B 的差异小结】12A 不装 certbot、不改 `server_name`、不做重定向、不用续期;代价只是首次访问点一次警告。

## 12B. 方案二(有域名):Let's Encrypt 免费证书

**前提:你已有一个域名,且 DNS A 记录已指向 ECS 公网 IP(大陆地域还需 ICP 备案通过,否则域名访问被阻断)**。用 certbot 自动配置,全程约 5 分钟。

### 12B.1 放行 443 端口
阿里云控制台 → 云服务器 ECS → 安全组 → 给该 ECS 加一条入方向规则:

| 端口 | 授权对象 | 说明 |
|---|---|---|
| 443 | `0.0.0.0/0` | HTTPS 入口 |

> 80 端口**保留不关**(Let's Encrypt HTTP-01 验证 + 80→443 重定向都要用它)。

### 12B.2 装 certbot
```bash
apt install -y certbot python3-certbot-nginx
```

### 12B.3 把 Nginx 的 server_name 从 _ 改成你的域名
编辑 `/etc/nginx/sites-available/nl2sql.conf`,把第 10.2 步 server 块里的:
```nginx
    server_name _;
```
改成:
```nginx
    server_name 你的域名.com;
```
重载:
```bash
nginx -t && systemctl reload nginx
```

> 必须先改 `server_name`,certbot 才能找到对应 server 块自动注入证书配置。

### 12B.4 申请证书并自动配 443
```bash
certbot --nginx -d 你的域名.com
```
交互提示按如下选:
- 输入你的邮箱(证书到期提醒用) → 回车;
- 同意服务条款 → `Y`;
- 是否接收营销邮件 → `N`;
- 选重定向策略 → `2`(把 HTTP 全部 301 重定向到 HTTPS,推荐)。

certbot 会自动改 nginx 配置:新增 443 server 块(带 `ssl_certificate` 路径)、把 80 的请求重定向到 443,然后 reload nginx。

### 12.5 验证
```bash
# 命令行
curl -I https://你的域名.com/actuator/health
# 期望 HTTP/2 200,status 字段 UP

# 验证 80 自动跳 443
curl -I http://你的域名.com
# 期望 HTTP/1.1 301 Moved Permanently,Location 指向 https://...
```

浏览器访问 `https://你的域名.com`,应见地址栏锁标 + 前端登录页。

### 12B.6 确认自动续期
Let's Encrypt 证书 90 天过期。certbot 装好后自带 systemd timer 自动续期,确认它激活:
```bash
systemctl list-timers | grep certbot
# 应看到 certbot.timer 一行,状态为 active(待运行)

# 手动试跑续期(只验证流程,不会真续)
certbot renew --dry-run
# 期望 "Congratulations, all simulated renewals succeeded"
```

> 走完这一步,站点就是 `https://你的域名.com` 全程加密访问;前端 axios `baseURL: '/api/v1'` 仍是相对路径,自动走 HTTPS,无需改前端。

## 13. 常见问题排查

| 症状 | 排查方向 | 命令 |
|---|---|---|
| `systemctl status` 显示 failed | 多半 jar 路径/权限或环境变量错 | `journalctl -u nl2sql-app -n 50` 看堆栈 |
| 启动报 `Access denied for user 'root'` | `DB_PASSWORD` 与 MySQL 容器密码不一致 | 核对 `/etc/default/nl2sql-app` 与第 4 步 |
| Flyway 迁移失败 `OutOfMemory` | MySQL 容器 512m 不够 | `docker update --memory=768m mysql` 后重启应用 |
| 问数返回 5001(模型超时)或友好提示 | `DASHSCOPE_API_KEY` 错或网络不通 | 服务器上 `curl https://dashscope.aliyuncs.com/compatible-mode/v1/models -H "Authorization: Bearer <key>"` |
| 问数返回 4001(非问数) | 输入不是问数意图,正常 | 换个问法,如"上月销售额" |
| `/actuator/health` 返回 404 | Nginx 没代理 actuator(第 7.2 步漏做) | 补 `location = /actuator/health` |
| 服务挂了不自动重启 | systemd 未配 Restart | 确认 `deploy/nl2sql-app.service` 含 `Restart=on-failure` |
| 日志找不到 | 默认走 journalctl 不是文件 | `journalctl -u nl2sql-app -f` 实时看 |
| 问数慢(>10s) | 首次冷查询正常;持续慢查模型超时 | LangFuse 看 trace,或换 `qwen-plus` |
