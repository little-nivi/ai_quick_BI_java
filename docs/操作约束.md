# 服务器操作约束（Agent 执行规则）

> 给所有后续协作的 Coding Agent / LLM Coding Assistant 的硬约束。
> 本项目 ECS 服务器（123.57.53.23 / root + 密码登录）出于安全考虑，**不允许 Agent 端自行通过 SSH / SCP / Shell('ssh ...') 等工具直连或上传文件**。所有服务器操作必须以「给出命令、用户在 SSH 终端手动执行并把输出贴回」的方式进行。

## 强制约束

1. **禁止在 Agent 侧用任何工具执行 SSH / SCP**
   - 不得调用 `Shell('ssh root@IP ...')`、`Shell('scp ...')`、`Shell('curl -T ...')` 或任何需要向服务器发起 TCP 连接的 Shell 命令
   - 同样禁止 `run_mcp` / 其他 MCP 工具里的远程执行

2. **部署流程全部拆成「本地 + 用户手动」两段**
   - 本地可执行：`mvn compile`、`mvn -DskipTests package`、`npm run build`、`tar cf dist.tar ...`（在 Windows 开发机上安全的本地命令可以直接跑）
   - **上传和服务器操作只给命令文本，由用户在 PowerShell/SSH 里执行**，典型格式：
     - PowerShell：`scp target\xxx.jar root@IP:/opt/nl2sql/xxx.jar.new`
     - SSH：`systemctl stop nl2sql-app && cp ... && chown ... && systemctl start ...`

3. **默认服务器是 root + 密码登录**
   - 不要假设密钥对、不要假设已配置 ssh-agent、不要写 `ssh -i key.pem`
   - 所有 `ssh` / `scp` 命令里不得硬编码密码，由用户在密码提示符下输入

4. **每段命令前说明预期输入/输出**
   - 比如：「执行后预期看到 `code=2000` + token」「如果大小不是 36~37MB 说明 SCP 未传完整，重新跑一次」
   - 出现分支场景（例如“如果日志里出现 X 则走 A，出现 Y 走 B”），分支条件要写得可机械判断，不要含糊

5. **换 jar 三步必须固化**
   任何「换后端 jar」的操作，命令文本里必须包含：
   ```
   systemctl stop nl2sql-app
   cd /opt/nl2sql
   cp nl2sql-app.jar nl2sql-app.jar.ok
   mv nl2sql-app.jar.new nl2sql-app.jar
   chown www-data:www-data nl2sql-app.jar
   systemctl start nl2sql-app
   sleep 25 && journalctl -u nl2sql-app -n 12 --no-pager | tail
   ```
   其中 **`cp nl2sql-app.jar nl2sql-app.jar.ok`** 永不省略（.ok = 已知可启动的保险包，启动失败立即回滚）。

6. **前端根目录以服务器实际 nginx root 为准，不要硬写 /var/www/nl2sql**
   - 每次首次执行 nginx 相关，先让用户跑 `nginx -T 2>&1 | grep -E "^\s*root\s"` 取实际目录，再基于该目录写后续命令
   - 若用户之前已经确认过 root = `/opt/nl2sql/frontend/dist`，以该路径为准

## 推荐的协作格式（对 Agent 的输出要求）

所有涉及服务器操作的回答，按以下结构给出，不要夹杂假设执行结果：

```
## ▶ 需要你手动做的事（PowerShell / SSH）

### 本地（PowerShell）
```powershell
<命令 1>
<命令 2>
```

### 服务器（SSH）
```bash

<预期：看到 Started Nl2sqlApplication>
```bash
<命令 2>
<预期：code=2000 total=21>
```

| 你看到什么 | 说明 | 下一步 |
|---|---|---|
| ... | ... | ... |
```

## 历史踩坑记录（避免重犯）

| 时间 | 坑 | 修复/教训 |
|---|---|---|
| 2026-09-01 晚 | Nginx root 路径按默认经验写成 `/var/www/nl2sql`，但服务器实际是 `/opt/nl2sql/frontend/dist`，tar 解压到不存在目录报错 → 前端资源丢失 | 强制先 `nginx -T | grep root` 取实际路径 |
| 2026-09-02 凌晨 | `Set.of(...)` 里中文助词重复写了“啊”→ 静态初始化抛 `IllegalArgumentException: duplicate element` → BeanCreationException → 应用启动失败但 systemd 自动重启 14 次，看起来像登录失败 | **任何新增静态集合都要检查重复元素**，并且部署后必检查「Started Nl2sqlApplication」而不是只看 status=active |
| 2026-09-02 凌晨 | Agent 直接用 Shell('ssh ...') 和 Shell('scp ...') 尝试跑服务器命令，因密码交互未配置失败，且用户明确要求“不可执行” | 写入本 Claude.md，强制执行约束第 1 条 |
| 2026-08-31 | `rm -rf /var/www/nl2sql/*` 连同空壳目录一起删掉，tar 解压时报 `No such file or directory` | 需要写入目标目录的命令，前一步先 `mkdir -p <path>` |
