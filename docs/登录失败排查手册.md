# NL2SQL 登录失败 · 端到端排查手册（按优先级顺序跑）

适用：前端输完密码点登录 → 出现「登录失败 / 白屏 / 转圈不响应」。

> **铁律 1：先判「SSH 能不能连上」，再谈别的。**
> SSH 连不上 + 昨天还好好的 → 99% 是 swap thrashing（Bug D），直接跳到 §1 紧急恢复。
>
> **铁律 2：502 / 503 永远先查后端 nl2sql-app 服务状态，不要一上来改 Nginx。**
> 只有当 127.0.0.1:8080 直连登录 OK，但 /api/v1/* 返回 502/超时 → 才走 §5 Nginx 段。

---

## §0. 登录请求的 4 段链路（定位用）

```
浏览器 (HTTPS)
    │
    ▼
① Nginx (443/80)  ──►  location /api/  proxy_pass  http://127.0.0.1:8080;
    │
    ▼
② Spring Boot 内嵌 Tomcat :8080  ──►  AuthController /api/v1/auth/login
    │
    ▼
③ HikariCP → MySQL 容器 127.0.0.1:3306（查 users 表 + BCrypt 校验密码）
    │
    ▼
④ JWT 生成 → 返回 2000 + { token, user }
```

任何一段出问题都会表现为“登录失败”，**按顺序从右到左查**（先查最内层后端应用，再查数据库、最后 Nginx / 网络）。

---

## §1. 紧急恢复：SSH 连不上或卡到爆炸（swap thrashing）

### 现象
- SSH 连接超时 / 输入密码后几分钟没反应 / 连进去了但敲一行命令 10 秒才出结果
- 重启 ECS 后短暂恢复正常（1~2 小时），然后复发
- 阿里云监控有「实例存储性能达到规格上限」= swap 带宽被打满

### 立即急救（SSH 能勉强连上时）
```bash
# 1) 先强杀大内存进程，保证 SSH 响应回到正常速度
systemctl stop nl2sql-app
docker stop mysql
swapoff -a && swapon -a           # 清空 swap 占用，立即解除换页 I/O 风暴
echo 3 > /proc/sys/vm/drop_caches

# 2) 重新拉起
docker start mysql
sleep 10
systemctl start nl2sql-app
sleep 30

# 3) 立刻看内存水位
free -h
```

### 根因 & 永久修复（Bug D 已固化在部署教程里）
- JVM 参数：`-Xms256m -Xmx704m -XX:MaxMetaspaceSize=256m -XX:+UseG1GC`（已写 nl2sql-app.service）
- MySQL 容器：`docker update --memory=384m mysql`（Flyway 迁移时临时升到 768m，迁完降回）
- 系统：`vm.swappiness=10`（已写 `/etc/sysctl.d/99-swap.conf`）
- earlyoom 守护：`apt install -y earlyoom && systemctl enable --now earlyoom`（<10% 内存时主动杀大内存进程，避免整机冻结）

## §2. SSH 能连上，nl2sql-app 服务诊断

**每次只跑一组命令，把整组输出贴给排查者。**

### §2.1 服务活着吗？启动成功了吗？
```bash
systemctl status nl2sql-app --no-pager | head -15
echo "====="
journalctl -u nl2sql-app -n 80 --no-pager | tail -80
```

**判定对照表**：

| 你看到的现象 | 含义 | 下一步 |
|---|---|---|
| `Active: active (running)` + 最后有 `Started Nl2sqlApplication in Xs` | ✅ 正常启动 | 继续 §2.4 |
| `Active: failed` 或 `inactive (dead)` | ❌ 已退出 | 找 journalctl 里最后一个 ERROR/Exception |
| `restart counter is at N`（N ≥ 2） | ❌ 连续崩溃，systemd 在自动重启 | 必然能在日志里找到 `BeanCreationException / OutOfMemoryError / SQLException / NoClassDefFound` 等根因；**99% 的情况是刚换的新 jar 启动失败（代码写错/依赖缺失/字段重复）** → 立刻回滚 `cp nl2sql-app.jar.ok nl2sql-app.jar` |
| 只看到 Spring Boot banner、但最后没有「Started Nl2sqlApplication」 | ⏳ 启动中（2G 实例要 20~25 秒）| `sleep 15` 再查一次 |
| 出现 `BeanCreationException: Error creating bean with name 'xxx' ` | ❌ Spring Bean 初始化失败 | 看 Caused by: 那行。例如 `duplicate element` 就是静态集合里写了重复值 |
| 出现 `SQLException: Access denied for user 'root'@'127.0.0.1'` | ❌ DB 密码对不上 | §3 |

### §2.2 端口 8080 真的在监听吗？
```bash
ss -lntp | grep 8080
# 或者：lsof -i :8080
# 或者：curl -s -o /dev/null -w "HTTP=%{http_code}\n" http://127.0.0.1:8080/actuator/health
```
- `HTTP=200` → Tomcat OK
- `HTTP=000` / Connection refused → 应用未完成启动（或启动失败），看 §2.1 日志

### §2.3 后端直连登录（绕过 Nginx，最关键的一步）
```bash
curl -s -X POST http://127.0.0.1:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | head -c 600
echo
```

**判定**：
- ✅ `code=2000` + `data.token=...` → **后端本身登录 100% 正常**，登录失败一定在 Nginx/网络/浏览器（§5 / §6）
- ❌ `code=40101` + 用户名或密码错误 → 密码不是 `admin123`，改正确密码重跑；如果忘密码 → §3.3 重置
- ❌ `code=5000` 或 `SQLException` → 数据库连接问题（§3）
- ❌ Connection refused / 空 → 回到 §2.1，应用没起来

### §2.4 内存 + swap 水位（长期稳定性）
```bash
free -h
journalctl -u earlyoom -n 5 --no-pager
```
- Swap 已用 > 300MB 且可用内存 < 200MB → 有 OOM 风险（§1 永久修复再跑一遍确认）

## §3. MySQL 数据库诊断

### §3.1 容器活着吗？
```bash
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Size}}"
```
- 状态是 `Up X days` → OK
- `Exited(137)` / `Exited(1)` → 已退出（137 = 被 OOM kill）
  ```bash
  docker start mysql
  sleep 12
  docker logs mysql --tail 20 2>&1 | tail -20
  ```

### §3.2 本地直连 DB（验证账号密码）
```bash
# 密码用你实际的（部署时 $MYSQL_ROOT_PASSWORD）
docker exec mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "SELECT 1;" 2>&1 | tail -5
```
- `1` → 连接 OK
- `Access denied` → `/etc/default/nl2sql-app` 里的 `DB_PASSWORD` 和 MySQL 容器启动时的 `MYSQL_ROOT_PASSWORD` 对不上

### §3.3 密码/用户表重置（ admin 密码忘了或输错锁死）
```bash
docker exec mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" nl2sql \
  -e "SELECT user_id, username, status, role FROM users;"
```
- 如果 `status='locked'` → `UPDATE users SET status='active' WHERE username='admin';`
- 硬重置 admin 密码为 `admin123`（生成 BCrypt 哈希）：
  ```bash
  # 用 Java 生成或直接用预置 hash。预置 admin123 是 $2a$10$N.zmdr9k7uOCQb376NoUnuTJ8iAt6Z5EHsM8lE9lBOsl7iAtkUfDEm （示例）
  docker exec mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" nl2sql \
    -e "UPDATE users SET password='PUT_BCRYPT_HASH_HERE', status='active' WHERE username='admin';"
  ```

## §4. 环境变量 & 配置文件（部署后老出问题的首犯）

```bash
cat /etc/default/nl2sql-app        # 所有敏感变量都在这儿（DB_PASSWORD / DASHSCOPE_API_KEY / LANGFUSE_* / JWT_SECRET）
echo "===== nl2sql-app.service ====="
cat /etc/systemd/system/nl2sql-app.service
echo "===== 验证 service 是否加载到了变量 ====="
systemctl show nl2sql-app -p Environment | tr ' ' '\n' | grep -E "^(DB_|DASHSCOPE|LANGFUSE|JWT)"
```

**最常见 3 个配置错**：
1. `DB_PASSWORD` 不等于启动 MySQL 容器时的 `MYSQL_ROOT_PASSWORD` → Access denied（§3.2）
2. `DASHSCOPE_API_KEY` 过期或为空 → 查询接口全挂（虽不直接影响登录，但后续会报错）
3. 改了 `/etc/default/nl2sql-app` 后**忘了 `systemctl daemon-reload && systemctl restart nl2sql-app`** → 变量永远是旧值

## §5. Nginx 链路（502 / 504）

§2.3 **后端直连登录成功但浏览器登录失败** → 才走到这里。

```bash
# 5.1 先看 nginx -t 是否语法 OK
nginx -t

# 5.2 80 / 443 分别打
echo "===== 80 ====="
curl -s -X POST http://127.0.0.1/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | head -c 400
echo
echo "===== 443 ====="
curl -sk -X POST https://127.0.0.1/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | head -c 400
echo
```

**502 对照表**：
| 症状 | 根因 | 修复 |
|---|---|---|
| 502 + `connect() failed (111: Connection refused) while connecting to upstream` | 后端 nl2sql-app 压根没启动（8080 没监听）| §2 启动后端 |
| 504 Gateway Time-out | 后端启动超过 60 秒或卡死在 DB 连接 | 看后端日志，通常是数据库连不上/Hikari hang住 |
| HTTPS 502 但 HTTP 正常 | 443 server block 没写 `proxy_pass http://127.0.0.1:8080;` | 检查 sites-enabled 下的 server 块 |
| 403 Forbidden | Nginx 目录权限（`/opt/nl2sql/frontend/dist` 不是 `www-data:www-data`）| `chown -R www-data:www-data /opt/nl2sql/frontend` |

```bash
# 5.3 看实际加载了哪些 root + proxy_pass
nginx -T 2>&1 | grep -niE "^\s*root\s|proxy_pass|^\s*listen\s|^\s*server_name\s"
```

## §6. 浏览器端问题（后端 + Nginx 全 OK，但浏览器还是登不上）

### 6.1 F12 → Network 看 `/api/v1/auth/login` 响应
- Status 是 200，但响应体是 `code=40101` → 密码错误（§3.3 重置）
- Status 是 200，但 `Set-Cookie` 为空 → JWT 是 body 里的 `data.token` 走 localStorage 逻辑，不是 Cookie（本项目鉴权方式是 Bearer Token 存 localStorage，所以没有 Set-Cookie 是正常的）
- Status 是 404 → URL 写错，检查前端 `baseURL` 是否 `/api/v1`
- Status 是 0 / blocked → CORS。确认生产环境前后端同源（Nginx 统一提供静态 + 反代 API，不会有 CORS；如果直接开 file:// 打开 html 就会有）

### 6.2 刷新缓存
登录失败后 302 跳转/缓存异常：Ctrl+Shift+R 或 隐私模式重访问。

## §7. 快速检查清单（1 分钟能跑完的「5 问」）

只要登录失败，按顺序回答 5 个问题，95% 的故障能秒定位：

| 序号 | 问题 | 命令 |
|---|---|---|
| 1 | SSH 能连上吗？ | → 连不上 = §1 OOM swap thrashing |
| 2 | nl2sql-app 最后有 Started 吗？ | `journalctl -u nl2sql-app -n 15 | tail` → 没有 = §2.1 |
| 3 | 127.0.0.1:8080 直连登录返回 2000+token？ | §2.3 curl → 没有 = 后端/DB 问题 |
| 4 | 经过 Nginx (80/443) 也返回 2000？ | §5 curl → 没有 = §5 Nginx 反代 |
| 5 | 浏览器里返回 2000？ | §6.1 F12 → 不是 = Cookie/CORS/前端缓存 |

## 附录：换 jar 之后立刻启动失败的标准急救流程

每次换 jar 之后都可能因为代码 bug 启不来（比如 Set.of 重复值导致 ExceptionInInitializerError）。**不要等 systemd 重启 14 次**，按这条走：

```bash
# 1) 立即停，别让它反复挂反复重启写满磁盘日志
systemctl stop nl2sql-app

# 2) 只看最后一次启动的完整异常
journalctl -u nl2sql-app --since "5 minutes ago" --no-pager | grep -A 40 "ERROR\|Exception\|Caused by:" | head -80

# 3) 30 秒内回滚到上一版保险包
cp nl2sql-app.jar.ok nl2sql-app.jar
chown www-data:www-data nl2sql-app.jar
systemctl start nl2sql-app

# 4) 等服务起来后（§2.3 curl 返回 2000），再回头修代码
```

**记住**：生产环境部署的第一条规则是「**永远保留一份已知 OK 的 jar，叫 .ok 或 .bak，替换前先 cp 一份**」。
