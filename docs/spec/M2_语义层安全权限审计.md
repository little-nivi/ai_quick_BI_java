## 1. 业务目标 & 非功能需求（§2.1）

### 系统能力（M2 增量）

- 用户登录鉴权（JWT），按系统角色区分数据范围；
- 指标语义层匹配：命中预定义指标直接套模板 SQL；
- 业务术语映射：口语化表述 → 规范 SQL 表达；
- 审计日志：每次问数请求落库可追溯；
- SQL 校验升级为 AST 级白名单。

### 非功能需求（量化）

| 编号 | NFR | 值 | 测量方式 |
|---|---|---|---|
| NFR-5 | 权限注入后 SQL 仍可执行 | 100% | 注入后的 SQL 在只读库执行不报语法错 |
| NFR-6 | 指标匹配单次耗时 | ≤ 50ms | 自进入匹配逻辑至返回匹配结果 |
| NFR-7 | 审计写入不阻塞主链路超时 | 同步写，单条 INSERT ≤ 100ms | DB 耗时监控 |

### 安全红线（量化拦截触发条件）

| 编号 | 红线 | 拦截触发条件 | 拦截动作 |
|---|---|---|---|
| SR-4 | 越权访问拦截 | 请求携带 token 但 `data_scope != "all"`，生成 SQL 未包含该用户 region 过滤时，强制追加 region 过滤（权限注入不可绕过） | 注入 region 条件，不信任模型 |
| SR-5 | 鉴权失败 | 请求缺 Authorization 头 / token 无效 / token 过期 | 返回 401，不进入问数链路 |

> SR-1~SR-3（高危 SQL、只读连接、Prompt 注入）自 M1 延续，M2 不撤销。

## 2. 系统架构 & 模块划分（§2.2）

### 模块与职责（M2 增量）

| 模块 | 职责 | 依赖 |
|---|---|---|
| AuthService | 登录校验、JWT 签发与解析 | users 表 |
| JwtUtil | token 生成/校验（HS256） | 无 |
| MetricMatcher | 指标语义层匹配（D-13） | metric_definitions 表 |
| GlossaryMatcher | 业务术语映射 | business_glossary 表 |
| PermissionInjector | 根据 data_scope 追加 region WHERE（D-12） | 无 |
| AuditService | 审计日志落库（D-14） | audit_logs 表 |
| SqlValidator | 升级为 AST 级白名单（D-15） | JSqlParser |

依赖方向（无环）：`Controller → AuthService → JwtUtil`；`Controller → QueryService → {MetricMatcher, GlossaryMatcher, SqlGenerator, SqlValidator(AST), PermissionInjector, SqlExecutor, AuditService}`。

### 数据流（M2 升级后的问数链路）

```
用户 question + Authorization
  → Controller(鉴权 SR-5，校验，生成 traceId)
  → MetricMatcher(指标命中? 命中→模板SQL : 未命中→NL2SQL)
     → GlossaryMatcher(术语映射注入 prompt)
     → SqlGenerator(生成 SQL)
  → SqlValidator(AST 白名单 SR-1 + 语法)
  → PermissionInjector(data_scope != "all" 时注入 region WHERE，SR-4)
  → SqlExecutor(只读执行，30s 超时)
  → AuditService(写 audit_logs，D-14)
  → 返回 { code, message, data:{question, sql, columns, rows, row_count, latency_ms, matched_metric}, traceId }
```

### 外部依赖

| 依赖 | 版本/能力 | 说明 |
|---|---|---|
| 通义千问 | qwen-turbo（dev） | 生成 SQL + 模板 SQL 补条件 |
| MySQL 8.0 | 读写库（Flyway/写表）+ 只读库（查询） | 双数据源（ADR D-10） |

## 4. 接口契约（§2.4）

### REQ-402 登录接口

1. **路径/方式**：`POST /api/v1/auth/login`
2. **请求头**：`Content-Type: application/json`
3. **请求参数**：

| 参数 | 类型 | 必填 | 格式/范围 |
|---|---|---|---|
| username | string | 是 | 1–50 字符 |
| password | string | 是 | 1–100 字符 |

4. **正常返回**：`{ "code": 2000, "data": { "token": "<jwt>", "role": "operator", "data_scope": "华东,华南" }, "traceId": "..." }`
5. **异常场景**：

| 错误码 | 场景 | 降级/动作 |
|---|---|---|
| 4000 | username/password 缺失或空白 | 返回错误，不查库 |
| 40101 | username 不存在 / 密码错误 / 非系统账号 | 返回 40101 + 固定话术「用户名或密码错误」 |

### REQ-403 查询接口（M2 升级，扩展 REQ-401）

1. **路径/方式**：`POST /api/v1/query`（不变）
2. **请求头**：`Content-Type: application/json`；`Authorization: Bearer <token>`（**M2 起必填**）
3. **请求参数**：同 REQ-401（`question` 1–500 字符）
4. **正常返回**：在 REQ-401 基础上 `data` 增加 `matched_metric`（命中指标的 metric_name，未命中为 null）
5. **异常场景**（在 REQ-401 基础上新增）：

| 错误码 | 场景 | 降级/动作 |
|---|---|---|
| 401 | 缺 Authorization 头 / token 无效 / token 过期（SR-5） | 返回 401，不进入问数链路 |

> REQ-401 原有异常（4000/4003/5001/5003/5002/4290/5000 兜底）继续适用。

## 5. 核心业务逻辑（§2.5）

### REQ-506 指标语义层匹配（D-13）

- 遍历 `status='published'` 的 metric_definitions；
- 命中判定：`metric_name` 或 `synonyms` 中任一逗号分隔项**完整子串出现**在 `question` 中；
- 多指标命中 → 取匹配子串**最长**者；
- 命中 → 取该指标 `template_sql` 作为基础 SQL，交由 qwen 结合 question 补时间/维度条件（非纯静态替换）；
- 未命中 → 走 NL2SQL（M1 的 SqlGenerator）。

### REQ-507 权限注入（D-12、SR-4）

- 从 token 解析 `data_scope`；
- `data_scope == "all"` → 不注入；
- 否则按逗号拆分为区域列表，在生成 SQL 的 WHERE 子句强制追加 `AND region IN ('华东','华南')`（区域值经参数化/转义，防注入）；
- 注入位置：模型生成后、SqlValidator 校验后、SqlExecutor 执行前；不信任模型输出的任何权限字段。

### REQ-508 审计日志（D-14）

- 每次 `/api/v1/query` 无论成功或失败，均同步写一条 `audit_logs`；
- 字段来源：`user_id`/`role` 来自 token，`question`/`generated_sql`/`latency_ms`/`ip_address` 来自请求，`cache_hit=false`，`confidence` 为 NULL；
- 写库失败仅记 error 日志，不阻断主链路返回。

### REQ-509 SQL 校验升级（D-15）

- 用 JSqlParser 解析 SQL 为 AST；
- 校验：根语句类型为 `SELECT`（非 INSERT/UPDATE/DELETE/DDL）；
- 解析失败 → 记 error 日志，返回 5000；
- 根语句非 SELECT → 返回 4003；
- 替换 M1 的正则白名单（消除字符串字面量含关键字的误拦）。

### REQ-510 业务术语映射

- 遍历 `business_glossary`，将 question 中的 `term` 替换为 `mapping` 后注入 prompt，帮助 qwen 理解口语化表述（如"卖得最好"→"销量最高"）。

## 6. 边界 Case、兜底策略、验收标准（§2.6）

### 验收 Case（Given/When/Then）

```
TC-402-01（验证 REQ-402 登录成功）
Given: username/password 正确且 is_system_account=true
When:  调用 POST /api/v1/auth/login
Then:  返回 code=2000，data 含 token/role/data_scope

TC-402-02（验证 REQ-402 登录失败）
Given: username 不存在 或 password 错误 或 非系统账号
When:  调用 POST /api/v1/auth/login
Then:  返回 code=40101 + 固定话术「用户名或密码错误」

TC-403-01（验证 REQ-403 缺 token）
Given: 请求未带 Authorization 头
When:  调用 POST /api/v1/query
Then:  返回 code=401，不进入问数链路，不写审计

TC-507-01（验证 REQ-507 权限注入）
Given: operator 账号 data_scope="华东"，问"全国销售额"
When:  链路执行
Then:  生成 SQL 含 AND region IN ('华东')，且返回结果仅华东数据

TC-506-01（验证 REQ-506 指标命中）
Given: 问题含"销售额"，metric_definitions 存在 metric_name="销售额"
When:  链路执行
Then:  使用该指标 template_sql 作为基础 SQL

TC-509-01（验证 REQ-509 字符串字面量不误拦）
Given: qwen 返回 SQL 含字符串字面量 '请 DELETE 此订单'
When:  SqlValidator 校验
Then:  AST 判定为合法 SELECT，不返回 4003

TC-509-02（验证 REQ-509 DML 拦截）
Given: qwen 返回 sql = "DELETE FROM orders"
When:  SqlValidator 校验
Then:  返回 4003，不执行

TC-508-01（验证 REQ-508 审计写入）
Given: 一次成功的 query 请求
When:  链路完成
Then:  audit_logs 新增一条，cache_hit=false，user_id 与 token 一致
```

### 验收成功判定（M2 完成标准）

- 上表 8 条 TC 全部通过；
- 权限隔离正确率 100%（operator 只能看到 data_scope 内区域）；
- 指标命中准确率 ≥ 80%（预置 20 条指标 + 30 条术语映射下的命中测试）。
