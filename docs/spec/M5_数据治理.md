## 0. 非目标（不做）清单

M5 在 M4 基础上新增「Schema 变更检测 + 数据质量监控 + 指标口径审批流」。以下明确不做：

- 不做 Schema 指纹的 Caffeine L1 加速（M5 先 MySQL 持久化，L1 加速可选）
- 不做血缘的主动消息推送（邮件/IM），仅落库记录
- 不做前端告警面板（M6）
- 不做数据质量的自动修复（只告警，不自动改数据）
- 不做 LangFuse 观测（M6）

## 1. 业务目标 & 非功能需求（§2.1）

### 系统能力（M5 增量）

- Schema 变更检测：定时对比 information_schema 与存储指纹，变更告警；
- 数据质量监控：定时检查空值率/枚举漂移/数据量波动；
- 指标口径审批流：draft→published→deprecated 状态流转。

### 非功能需求（量化）

| 编号 | NFR | 值 | 测量方式 |
|---|---|---|---|
| NFR-14 | Schema 检测频率 | 每小时 1 次 | cron `0 0 * * * *` |
| NFR-15 | 数据质量检查频率 | 每日 1 次 | cron 每日凌晨 |
| NFR-16 | Schema 检测单次耗时 | ≤ 5s | 自任务启动至完成 |

### 安全红线（量化拦截触发条件）

| 编号 | 红线 | 拦截触发条件 | 拦截动作 |
|---|---|---|---|
| SR-9 | 越权审批 | 非 admin 角色调用审批/废弃接口 | 返回 4004，不改变 status |

> SR-1~SR-8 自 M1~M4 延续。

## 2. 系统架构 & 模块划分（§2.2）

### 模块与职责（M5 增量）

| 模块 | 职责 | 依赖 |
|---|---|---|
| SchemaChangeDetector | 定时对比 information_schema 与 schema_fingerprint，变更则记录+告警 | schema_fingerprint/schema_changes 表 |
| DataQualityMonitor | 定时检查空值率/枚举漂移/数据量波动 | data_quality_alerts 表 |
| MetricGovernanceService | 指标创建/审批/废弃（状态流转） | metric_definitions 表 |
| MetricController | 指标管理接口（admin 权限） | MetricGovernanceService |

依赖方向（无环）：`MetricController → MetricGovernanceService → metric_definitions`；`SchemaChangeDetector`/`DataQualityMonitor` 独立定时任务。

### 数据流

```
定时任务（@Scheduled）：
  SchemaChangeDetector → 计算 information_schema 新指纹 → 对比 schema_fingerprint 旧值 → 不一致→写 schema_changes + 更新指纹
  DataQualityMonitor → 计算空值率/枚举分布/数据量 → 超阈值→写 data_quality_alerts

接口：
  admin 调用 MetricController → MetricGovernanceService → 状态流转（draft→published→deprecated）
```

## 4. 接口契约（§2.4）

### REQ-407 创建指标

1. **路径/方式**：`POST /api/v1/metrics`
2. **请求头**：`Authorization: Bearer <token>`（admin，SR-9）
3. **请求参数**：

| 参数 | 类型 | 必填 | 格式/范围 |
|---|---|---|---|
| metric_name | string | 是 | 1–100 字符 |
| synonyms | string | 否 | ≤500 字符 |
| expression | string | 是 | 非空 |
| related_tables | string | 是 | 非空 |
| definition | string | 是 | 非空 |
| template_sql | string | 是 | 非空 |

4. **正常返回**：`{ "code": 2000, "data": { "metric_id": 21, "status": "draft" }, "traceId": "..." }`
5. **异常场景**：4000（参数非法）、4004（非 admin）、5000（兜底）

### REQ-408 审批指标

1. **路径/方式**：`POST /api/v1/metrics/{metricId}/approve`
2. **请求头**：`Authorization: Bearer <token>`（admin，SR-9）
3. **请求参数**：路径参数 metricId
4. **正常返回**：`{ "code": 2000, "data": { "status": "published" }, "traceId": "..." }`
5. **异常场景**：4000（metricId 不存在）、4004（非 admin）、4000（非 draft 状态不可审批）

### REQ-409 废弃指标

1. **路径/方式**：`POST /api/v1/metrics/{metricId}/deprecate`
2. **请求头**：`Authorization: Bearer <token>`（admin，SR-9）
3. **请求参数**：路径参数 metricId
4. **正常返回**：`{ "code": 2000, "data": { "status": "deprecated" }, "traceId": "..." }`
5. **异常场景**：4000（metricId 不存在）、4004（非 admin）

## 5. 核心业务逻辑（§2.5）

### REQ-522 Schema 变更检测（D-26/D-27）

- 定时任务（每小时）遍历 `information_schema.columns`，对每张业务表计算列结构 MD5 指纹；
- 对比 `schema_fingerprint` 表旧值：无记录→插入；不一致→写 `schema_changes`（change_type=field_added/field_modified 等）+ 更新指纹；
- 首次运行：为所有表建指纹，不告警。

### REQ-523 数据质量监控（D-28）

- 定时任务（每日凌晨）检查 orders 表：
  1. 空值率：`amount`/`order_date`/`region` 任一空值率 > 10% → 告警（null_rate）；
  2. 枚举漂移：region 某枚举值计数突然为 0（对比前 7 天）→ 告警（enum_drift）；
  3. 数据量波动：当日数据量 vs 前 7 天均值，波动 > 50% → 告警（volume_spike）。

### REQ-524 指标审批流（D-29）

- 创建：status=draft；
- 审批：仅 admin，draft→published；
- 废弃：仅 admin，published→deprecated；
- 非法状态流转（如 published→published、draft→deprecated）→ 4000。

### REQ-525 指标血缘（D-30）

- 指标变更（审批/废弃）时，查询 `metric_lineage` 是否有下游依赖；
- 有依赖 → 写告警记录（复用 data_quality_alerts，alert_type=metric_lineage_notice）；
- 不做消息推送（M6 前端展示）。

## 6. 边界 Case、兜底策略、验收标准（§2.6）

### 验收 Case（Given/When/Then）

```
TC-407-01（验证 REQ-407 创建指标）
Given: admin 提交合法指标参数
When:  调用 POST /api/v1/metrics
Then:  返回 metric_id，metric_definitions 新增 status=draft

TC-408-01（验证 REQ-408 审批）
Given: 存在 status=draft 的指标
When:  admin 调用 approve
Then:  status 变为 published

TC-409-01（验证 REQ-409 废弃）
Given: 存在 status=published 的指标
When:  admin 调用 deprecate
Then:  status 变为 deprecated

TC-407-02（验证 SR-9 越权审批）
Given: operator 角色调用 approve
When:  调用 POST /api/v1/metrics/{id}/approve
Then:  返回 4004，status 不变

TC-522-01（验证 REQ-522 Schema 变更检测）
Given: schema_fingerprint 表为空
When:  定时任务首次运行
Then:  为所有业务表建立指纹，不告警

TC-523-01（验证 REQ-523 空值率告警）
Given: orders.amount 空值率 > 10%
When:  数据质量任务运行
Then:  data_quality_alerts 新增 alert_type=null_rate
```
