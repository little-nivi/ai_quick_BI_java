## 0. 非目标（不做）清单

M3 在 M2 基础上新增「意图识别 + 置信度评估 + 反问澄清 + 数据溯源 + 自我修正 + 用户反馈闭环」。以下明确不做：

- 不做会话持久化（session_records 表 + Caffeine 写穿透，留 M4；M3 反问用无状态方式）
- 不做语义缓存 / 查询缓存（M4）
- 不做 LangFuse 全链路观测（M6）
- 不做前端（M6；反馈按钮与溯源面板由前端 M6 实现，M3 只提供后端接口）
- 不做 Schema BM25 召回
- 不做指标口径 UI 审批流（M2 已含后端审批，M5 完善）

## 1. 业务目标 & 非功能需求（§2.1）

### 系统能力（M3 增量）

- 意图识别：区分问数 / 非问数意图；
- 置信度评估：模型自评 0~1，按 0.85/0.60 分级；
- 反问澄清：低置信不执行，返回澄清问题；
- 数据溯源：返回结果附带查询依据；
- 自我修正：执行报错回传模型重试 ≤3 次；
- 用户反馈：正负反馈落库，负反馈进处理队列。

### 非功能需求（量化）

| 编号 | NFR | 值 | 测量方式 |
|---|---|---|---|
| NFR-8 | 自我修正单轮耗时 | ≤ 3 × 单次 LLM 调用 | 修正次数 × 单次耗时 |
| NFR-9 | 置信度评估不增加额外 LLM 调用 | 1 次调用同时返回 sql+confidence | 调用计数 |
| NFR-10 | 反问澄清平均生成耗时 | ≤ 2s | 自生成澄清至返回 |

### 安全红线（量化拦截触发条件）

| 编号 | 红线 | 拦截触发条件 | 拦截动作 |
|---|---|---|---|
| SR-6 | 非问数意图拦截 | LLM 返回 `is_query=false` | 返回 4001，不生成 SQL |
| SR-7 | 低置信拦截 | `confidence < 0.60` | 返回 4002 + 澄清问题，不执行 SQL |

> SR-1~SR-5（高危 SQL、只读、Prompt 注入、越权、鉴权）自 M1/M2 延续。

## 2. 系统架构 & 模块划分（§2.2）

### 模块与职责（M3 增量）

| 模块 | 职责 | 依赖 |
|---|---|---|
| IntentConfidenceEvaluator | 解析 LLM 返回的 is_query + confidence | LLM 输出 |
| ClarificationGenerator | 低置信时生成澄清问题与选项 | LLM |
| SelfCorrector | 执行报错回传模型修正（≤3 次） | SqlGenerator |
| TraceBuilder | 组装溯源信息（表/字段/SQL/指标/置信度） | 无 |
| FeedbackService | 反馈落库 + 定时轮询 pending 队列 | feedback_queue 表 |
| FeedbackController | 反馈提交接口 | FeedbackService |

### 数据流（M3 升级后的问数链路）

```
用户 question + Authorization
  → Controller(鉴权 SR-5，注入防御 SR-3，校验)
  → QueryService:
     1. 指标匹配(REQ-506) + 术语映射(REQ-510)
     2. LLM 生成 SQL + is_query + confidence（一次调用，D-16/D-17）
     3. is_query=false → 4001（SR-6）
     4. confidence < 0.60 → 4002 + 澄清（SR-7，D-18）
     5. 0.60 ≤ c < 0.85 → 中置信：执行 + 溯源标"中置信"（ADR D-05）
     6. c ≥ 0.85 → 高置信：直接执行
     7. AST 校验(REQ-509) → 权限注入(REQ-507) → 只读执行(REQ-503)
     8. 执行报错 → SelfCorrector 修正 ≤3 次（D-19，仅语法/字段类错误）
     9. TraceBuilder 溯源 + AuditService 审计(REQ-508)
  → 返回 { code, message, data:{question, sql, columns, rows, row_count, latency_ms, matched_metric, confidence, trace}, traceId }
```

## 3. 数据模型（§2.3）

### REQ-307 feedback_queue 表（用户反馈，P1-4）

| 字段 | 类型 | 可空 | 默认值 | 生命周期 |
|---|---|---|---|---|
| feedback_id | BIGINT PK AUTO_INCREMENT | 否 | — | 创建即生成 |
| user_id | BIGINT | 否 | — | 写入即冻结 |
| question | TEXT | 否 | — | 写入即冻结 |
| generated_sql | TEXT | 是 | NULL | 写入即冻结 |
| result_hash | VARCHAR(64) | 是 | NULL | 写入即冻结 |
| feedback_type | VARCHAR(10) | 否 | — | positive/negative，写入即冻结 |
| user_comment | TEXT | 是 | NULL | 写入即冻结 |
| user_corrected_sql | TEXT | 是 | NULL | 写入即冻结 |
| status | VARCHAR(20) | 否 | `pending` | positive→resolved；negative→pending→analyzed→added_to_fewshot→resolved |
| created_at | TIMESTAMP | 否 | CURRENT_TIMESTAMP | 写入即冻结 |
| processed_at | TIMESTAMP | 是 | NULL | 处理时写入 |

状态机：`pending → analyzed → added_to_fewshot → resolved`；`positive` 类型创建即 `resolved`（D-20）。

## 4. 接口契约（§2.4）

### REQ-404 查询接口（M3 升级，扩展 REQ-403）

1. **路径/方式**：`POST /api/v1/query`（不变）
2. **请求头**：`Authorization: Bearer <token>`（延续 M2）
3. **请求参数**：同 REQ-401（question 1–500 字符）
4. **正常返回**：`data` 在 M2 基础上新增 `confidence`（double）与 `trace`（溯源对象）：

```json
"data": {
  "question": "...", "sql": "...", "columns": [...], "rows": [[...]],
  "row_count": 1, "latency_ms": 1234, "matched_metric": "销售额",
  "confidence": 0.92,
  "trace": { "tables": ["orders"], "fields": ["amount"], "metric": "销售额", "confidence": 0.92 }
}
```

5. **异常场景**（在 REQ-403 基础上新增）：

| 错误码 | 场景 | 降级/动作 |
|---|---|---|
| 4001 | LLM 返回 is_query=false（非问数意图，SR-6） | 返回 4001 + 固定话术「请提出数据查询相关问题」 |
| 4002 | confidence < 0.60（低置信，SR-7） | 返回 4002 + `data.clarification`（澄清问题 + 选项数组） |

### REQ-405 反馈提交接口

1. **路径/方式**：`POST /api/v1/feedback`
2. **请求头**：`Authorization: Bearer <token>`；`Content-Type: application/json`
3. **请求参数**：

| 参数 | 类型 | 必填 | 格式/范围 |
|---|---|---|---|
| question | string | 是 | 1–500 字符 |
| generated_sql | string | 否 | — |
| result_hash | string | 否 | ≤64 字符 |
| feedback_type | string | 是 | `positive` / `negative` |
| user_comment | string | 否 | ≤2000 字符 |
| user_corrected_sql | string | 否 | — |

4. **正常返回**：`{ "code": 2000, "data": { "feedback_id": 1 }, "traceId": "..." }`
5. **异常场景**：

| 错误码 | 场景 | 降级/动作 |
|---|---|---|
| 4000 | feedback_type 非法（非 positive/negative） | 返回 4000 |
| 401 | 缺 token / 无效 | 返回 401 |

## 5. 核心业务逻辑（§2.5）

### REQ-511 意图识别 + 置信度评估（D-16/D-17）

- LLM 输出结构升级为 `{ "sql": string, "explanation": string, "is_query": boolean, "confidence": double }`；
- `is_query=false` → 4001；`confidence < 0.60` → 4002 + 澄清；
- `0.60 ≤ confidence < 0.85` → 中置信：执行 SQL，溯源标 `confidence_level="中"`（ADR D-05：中置信额外自检放行）；
- `confidence ≥ 0.85` → 高置信：执行，溯源标 `confidence_level="高"`。

### REQ-512 反问澄清（D-18）

- 低置信时，调 LLM 生成澄清问题 + 2~4 个选项；
- 返回 4002 + `data.clarification = { "question": "...", "options": ["销售额","利润","订单量"] }`；
- 前端将「原问题 + 用户选择」拼成新 question 重新 POST（无状态，不落 session 表）。

### REQ-513 自我修正（D-19）

- 仅当 SQL 执行阶段抛出语法/字段类异常（SQLSyntaxErrorException、BadSqlGrammarException、字段不存在）时触发；
- 将「原 SQL + 错误信息 + question」回传模型重新生成，最多 3 次；
- 3 次仍失败 → 返回 5000 + 固定话术「查询失败，请换个问法」；
- 超时（5002）不触发修正，直接返回。

### REQ-514 数据溯源（P1-2）

- 每次成功返回附 `trace`：`tables`（orders）、`fields`（提取 SQL 中字段）、`metric`（命中指标名或 null）、`confidence`（数值 + 分级）。

### REQ-515 用户反馈（D-20）

- 正负反馈均落库；`positive` → `status=resolved`；`negative` → `status=pending`；
- `FeedbackService` 用 Spring `@Scheduled` 定时（每 5 分钟）轮询 `status='pending'` 的记录并打日志（M3 仅轮询日志，分析/补 Few-Shot 留人工）。

## 6. 边界 Case、兜底策略、验收标准（§2.6）

### 验收 Case（Given/When/Then）

```
TC-404-01（验证 REQ-511 非问数拦截）
Given: question = "今天天气怎么样"
When:  链路执行，LLM 返回 is_query=false
Then:  返回 code=4001，未生成/执行 SQL

TC-404-02（验证 REQ-511 低置信反问）
Given: LLM 返回 confidence=0.4
When:  链路执行
Then:  返回 code=4002 + data.clarification（question + options 非空），未执行 SQL

TC-404-03（验证 REQ-511 高置信直接执行）
Given: LLM 返回 confidence=0.95，sql 合法
When:  链路执行
Then:  返回 code=2000，data.confidence=0.95，trace.confidence_level="高"

TC-404-04（验证 REQ-511 中置信）
Given: LLM 返回 confidence=0.75
When:  链路执行
Then:  返回 code=2000，trace.confidence_level="中"

TC-405-01（验证 REQ-405 负反馈进队列）
Given: feedback_type="negative"
When:  调用 POST /api/v1/feedback
Then:  返回 feedback_id，feedback_queue 新增一条 status="pending"

TC-405-02（验证 REQ-405 正反馈直接 resolved）
Given: feedback_type="positive"
When:  调用 POST /api/v1/feedback
Then:  feedback_queue 新增一条 status="resolved"

TC-513-01（验证 REQ-513 自我修正）
Given: 首次执行抛语法错误（SQLSyntaxErrorException）
When:  链路执行
Then:  触发修正重生成，重试 ≤3 次；修正成功后返回 2000

TC-513-02（验证 REQ-513 修正 3 次仍失败）
Given: 连续 3 次执行均抛语法错误
When:  链路执行
Then:  返回 5000 + 固定话术「查询失败，请换个问法」
```

### 验收成功判定（M3 完成标准）

- 上表 8 条 TC 全部通过；
- 反问澄清准确率 ≥ 70%（模糊问题正确触发反问）；
- 自我修正成功率 ≥ 60%（注入语法错误 SQL 触发修正后成功）。
