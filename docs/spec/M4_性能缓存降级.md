## 0. 非目标（不做）清单

M4 在 M3 基础上新增「缓存抽象层（语义缓存+权限缓存）+ 降级链 + 会话写穿透 + LIMIT 注入 + 缓存监控」。以下明确不做：

- 不做 Schema 指纹缓存（Caffeine L1 + MySQL 持久化，留 M5 数据治理）
- 不做查询缓存、会话缓存（CacheService 里的另几类，收益低）
- 不做多模型降级（qwen-plus，dev 无该模型 key）
- 不做真正的多轮上下文记忆（session 机制，留后续）
- 不做 Redis 实现（RedisCacheServiceImpl 仅接口预留，不实现）
- 不做 LangFuse 观测（M6）
- 不做前端（M6）

## 1. 业务目标 & 非功能需求（§2.1）

### 系统能力（M4 增量）

- 语义缓存：重复问题 24h 内直接返回缓存结果；
- 权限缓存：role→data_scope 本地缓存；
- 降级链：模型超时 → 缓存兜底 → 友好提示；
- 会话写穿透：每次 Q&A 落库 session_records；
- LIMIT 注入：防大结果集；
- 缓存监控：命中率/容量埋点。

### 非功能需求（量化）

| 编号 | NFR | 值 | 测量方式 |
|---|---|---|---|
| NFR-11 | 缓存命中响应延迟 | ≤ 500ms | 命中时自进入 QueryService 至返回 |
| NFR-12 | 语义缓存命中率 | ≥ 30% | 命中次数 / 总请求次数 |
| NFR-13 | 缓存容量超限降级阈值 | estimatedSize ≥ 90% | Caffeine `stats().estimatedSize()` |

### 安全红线（量化拦截触发条件）

| 编号 | 红线 | 拦截触发条件 | 拦截动作 |
|---|---|---|---|
| SR-8 | 跨角色缓存串读 | 缓存 key 不含 role | 构造 key 时强制拼入 role（D-21），缺失则视为实现缺陷 |

> SR-1~SR-7 自 M1~M3 延续。

## 2. 系统架构 & 模块划分（§2.2）

### 模块与职责（M4 增量）

| 模块 | 职责 | 依赖 |
|---|---|---|
| CacheService | 通用缓存接口 get/put/evict/clear（D-25） | 无 |
| CaffeineCacheServiceImpl | 默认实现（L1 本地缓存） | Caffeine |
| SemanticCache | 语义缓存实例（key=hash(question+schema_version+role)） | CacheService |
| PermissionCache | 权限缓存实例（role→data_scope） | CacheService |
| LimitInjector | SQL 追加 LIMIT 1000 | 无 |
| SessionRecorder | 会话写穿透落库 session_records | session_records 表 |
| DegradationHandler | 降级链（超时→缓存兜底→提示） | SemanticCache |

依赖方向（无环）：`QueryService → {SemanticCache, PermissionCache, LimitInjector, SessionRecorder, DegradationHandler}`；三者均依赖 `CacheService`（接口）。

### 数据流（M4 升级后的问数链路）

```
用户 question + Authorization
  → Controller(鉴权 SR-5，注入防御 SR-3)
  → QueryService:
     0. 语义缓存检查（key=hash(question+schema_version+role)，命中→直接返回，cache_hit=true）
     1. 指标匹配 + 术语映射 + LLM 生成(含意图/置信度)
     2. 意图识别/置信度分级/反问（同 M3）
     3. AST 校验 → 权限注入 → LIMIT 注入 → 只读执行（报错→自我修正）
     4. 溯源 + 审计（cache_hit 字段标记）
     5. 会话写穿透（写 session_records）
     6. 语义缓存写入（未命中时）
  → 降级链：模型超时 → 查语义缓存最近成功结果 → 友好提示
```

## 3. 数据模型（§2.3）

### REQ-308 session_records 表（会话写穿透，D-24）

| 字段 | 类型 | 可空 | 默认值 | 生命周期 |
|---|---|---|---|---|
| record_id | BIGINT PK AUTO_INCREMENT | 否 | — | 创建即生成 |
| user_id | BIGINT | 否 | — | 写入即冻结 |
| question | TEXT | 否 | — | 写入即冻结 |
| generated_sql | TEXT | 是 | NULL | 写入即冻结 |
| cache_hit | BOOLEAN | 否 | false | 写入即冻结 |
| created_at | TIMESTAMP | 否 | CURRENT_TIMESTAMP | 写入即冻结 |

## 4. 接口契约（§2.4）

### REQ-406 查询接口（M4 升级，扩展 REQ-404）

1. **路径/方式**：`POST /api/v1/query`（不变）
2. **请求头**：`Authorization: Bearer <token>`（延续）
3. **请求参数**：同 REQ-401（question 1–500 字符）
4. **正常返回**：`data` 在 M3 基础上新增 `cache_hit`（boolean）：

```json
"data": {
  "question": "...", "sql": "...", "columns": [...], "rows": [[...]],
  "row_count": 1, "latency_ms": 234, "matched_metric": "销售额",
  "confidence": 0.9, "trace": {...}, "cache_hit": true
}
```

5. **异常场景**：在 REQ-404 基础上，降级链兜底话术固定为「系统繁忙，请稍后重试」（对应 5001）。

## 5. 核心业务逻辑（§2.5）

### REQ-516 语义缓存（D-21、P1-1/2/3）

- key = `hash(question + schema_version + role)`；
- 命中 → 直接返回，`cache_hit=true`，不调用 LLM，仍写审计（cache_hit=true）；
- 未命中 → 走完整链路，成功后写入缓存（TTL 24h，maximumSize=500）；
- 空结果也缓存（防穿透，TTL 5 分钟）；
- 防击穿：Caffeine 内置 CacheLoader 原子加载。

### REQ-517 权限缓存（P1-4）

- key = role，value = data_scope；
- TTL 1h；变更频率极低，仅在 AuthService 登录后写入。

### REQ-518 降级链（D-23、P1-5）

- 模型 API 超时（5001）→ 查语义缓存该问题最近成功结果；
- 命中 → 返回缓存结果（降级成功）；
- 未命中 → 返回 5001 + 固定话术「系统繁忙，请稍后重试」。

### REQ-519 会话写穿透（D-24）

- 每次 query 成功或失败，写一条 `session_records`（user_id/question/generated_sql/cache_hit）；
- 写库失败仅记 error 日志，不阻断主链路。

### REQ-520 LIMIT 注入（P1-6）

- 生成 SQL 校验后、执行前，若 SQL 无 `LIMIT` 子句，追加 `LIMIT 1000`。

### REQ-521 缓存监控埋点（P1-7）

- 通过 Caffeine `Cache.stats()` 暴露命中率、容量到 Actuator `/actuator/metrics`；
- 容量超 90% 时降级为跳过缓存（直接走完整链路）。

## 6. 边界 Case、兜底策略、验收标准（§2.6）

### 验收 Case（Given/When/Then）

```
TC-406-01（验证 REQ-516 缓存命中）
Given: 同一问题（同 role）第 1 次查询完成
When:  第 2 次相同问题到达
Then:  cache_hit=true，latency_ms ≤ 500ms，未调用 LLM

TC-406-02（验证 REQ-516 跨角色隔离）
Given: admin 与 operator 问同一问题
When:  两次查询
Then:  各自返回对应权限范围的数据（缓存 key 含 role，不串读）

TC-406-03（验证 REQ-520 LIMIT 注入）
Given: 生成 SQL 无 LIMIT
When:  执行前
Then:  SQL 追加 LIMIT 1000

TC-406-04（验证 REQ-518 降级链）
Given: LLM 调用超时
When:  语义缓存有该问题最近成功结果
Then:  返回缓存结果，不报 5001

TC-406-05（验证 REQ-518 降级兜底）
Given: LLM 调用超时，且缓存无该问题结果
When:  查询
Then:  返回 5001 + 固定话术「系统繁忙，请稍后重试」

TC-406-06（验证 REQ-519 会话写穿透）
Given: 一次查询完成
When:  链路结束
Then:  session_records 新增一条，cache_hit 字段正确
```

### 验收成功判定（M4 完成标准）

- 上表 6 条 TC 全部通过；
- 语义缓存命中率 ≥ 30%（重复查询场景）；
- 缓存命中响应延迟 ≤ 500ms。
