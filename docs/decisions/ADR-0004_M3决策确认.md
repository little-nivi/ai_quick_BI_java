# ADR-0004 M3 决策与默认值确认

> 状态：已决（D-16~D-20 + P1 全部确认）
> 日期：2026-08-22
> 确认人：用户（"全部照单"）
> 上游依据：ADR-0001（D-02/D-05 置信度阈值与中置信行为）、M3 Spec v0.1 决策清单

---

## D-16 置信度评估实现方式（方案 A）

- **决策**：qwen 生成 SQL 时同一次调用顺带返回 `confidence`（0~1 小数），不单独二次评估。
- **理由**：省一次 LLM 调用与 Token；M3 用 qwen-turbo 自评足够。

## D-17 意图识别（方案 A，与置信度合并）

- **决策**：同一次 LLM 调用返回 `is_query`（boolean）+ `confidence`。`is_query=false` → 4001（意图识别非问数）。
- **理由**：意图识别与置信度合并进一次调用，与 D-16 统一。

## D-18 反问澄清会话机制（方案 A，轻量无状态）

- **决策**：M3 反问用「前端拼新问题」的无状态方式：返回 4002 + `data.clarification`（澄清问题 + 选项数组），前端将「原问题 + 用户选择」拼成新 question 重新 POST。**不落 session_records 表**（会话持久化留 M4）。
- **理由**：避免把 M4 会话持久化提前；M3 反问无需服务端存状态。

## D-19 自我修正触发与边界

- **决策**：自我修正与反问澄清**互斥分支**：
  - 置信度低 → 反问澄清（不执行 SQL）；
  - 置信度够 → 执行 → 报错 → 自我修正（最多 3 次）。
- **理由**：修正只针对「执行阶段报错」，不针对「置信度低」。

## D-20 用户反馈触发范围（方案 A）

- **决策**：正负反馈都落库 `feedback_queue`；`positive` 直接 `resolved`，`negative` 进 `pending` 队列等分析师处理。
- **理由**：正反馈也留痕可追溯，但只消耗处理资源的负反馈进队列。

## P1 默认值（已确认）

| 编号 | 项 | 确认值 |
|---|---|---|
| P1-1 | confidence 字段 | 0~1 小数，分级阈值 0.85/0.60（ADR D-02） |
| P1-2 | 溯源字段 | data 增加 `trace`：tables / fields / sql / metric / confidence |
| P1-3 | 反问返回 | 4002 + `data.clarification`（澄清问题 + 选项数组） |
| P1-4 | feedback_queue 表 | feedback_id/user_id/question/generated_sql/result_hash/feedback_type/user_comment/user_corrected_sql/status/created_at/processed_at |
| P1-5 | 自我修正错误类型 | 仅 SQLSyntax/BadSqlGrammar/字段不存在触发修正；超时 5002 不修正 |
| P1-6 | is_query 判定 | qwen 返回 is_query boolean，false → 4001 |
